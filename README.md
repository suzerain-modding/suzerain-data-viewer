# Suzerain Data Viewer

Suzerain Data Viewer inspects JSON exports from [Suzerain Data Dumper](https://github.com/suzerain-modding/suzerain-data-dumper). Use a local SQLite/FTS5 index for focused CLI queries, or generate a static HTML site for browsing. Neither mode needs the running game or its assemblies.

## Installation and Usage

Suzerain Data Viewer has builds for Windows x64 and Linux x64 (glibc).

1. Download the latest release from [releases](https://github.com/suzerain-modding/suzerain-data-viewer/releases). Place it anywhere on your computer.
2. Use [Suzerain Data Dumper](https://github.com/suzerain-modding/suzerain-data-dumper) to dump the game data.
3. Open terminal in the directory containing the files generated by Suzerain Data Dumper, or open terminal and `cd` to that directory.
4. Run the executable.
   - If on Windows, just copy and paste the path to the executable in the terminal to run it.
5. Select the JSON file to read.
6. Once done, open the generated `out/index.html` file to inspect.

## Indexed CLI queries

All commands except the no-argument interactive picker run without prompts. See
[the CLI guide](docs/CLI.md) for output contracts, provenance, limits and overwrite rules.
The examples use PowerShell; replace the executable name on Linux.

```powershell
# Import all supported JSON dumps in a directory (non-recursive).
.\suzerain_data_viewer.exe import 'C:/Suzerain/dumps'

.\suzerain_data_viewer.exe sources
.\suzerain_data_viewer.exe validate --check-files
.\suzerain_data_viewer.exe search EconomicOverview --kind conversations --pack Sordland
.\suzerain_data_viewer.exe node --pack Sordland --conversation-id 1 --entry-id 105
.\suzerain_data_viewer.exe neighbors --pack Sordland --conversation-id 1 --entry-id 105 --depth 1
.\suzerain_data_viewer.exe references GovernmentBudget --pack Sordland --language lua
.\suzerain_data_viewer.exe entity Turn01_EnT_EconomicOverview --kind ConversationData
```

These examples use the default `suzerain-data.sqlite` in the current directory.
For a different path, pass the same `--database PATH` to import and each query.
Results are JSON by default. Use `--help` or `<command> --help` for all options.
The original HTML picker still runs when the executable is invoked without arguments.

For explicit HTML conversion:

```powershell
.\suzerain_data_viewer.exe html --input 'C:/Suzerain/dumps/SuzerainDataDumper.conversations_Sordland.json' --output 'C:/Suzerain/html'
```

An existing HTML output directory is refused unless `--overwrite` is supplied and it
contains this version's `.sdv-output.json` marker. Old unmarked output directories
must be moved or a different output path chosen.

## Building from Source

The compiler is pinned in `rust-toolchain.toml` to Rust **1.95.0**. Install Rust with rustup, then
install the pinned toolchain once with `rustup toolchain install 1.95.0`. The preflight
does not install compilers automatically. Rustup selects the pin when building this checkout.
On Windows, also install Visual Studio C++ Build Tools with the Windows SDK and MSVC x64 tools.
On Linux, a C compiler and linker are required to build the bundled SQLite source.
The .NET SDK and game assemblies are not needed to compile Data Viewer. SQLite
(including FTS5) is built from bundled source; no separate SQLite installation is needed.

```powershell
pwsh -NoProfile -File scripts/preflight.ps1
cargo build --locked
cargo build --locked --release
```

The preflight reports compiler versions, the Windows MSVC toolset where applicable, and
output-directory write access. It does not build, convert dumps, or modify the input data.

Output defaults to `target/debug/` or `target/release/`. To keep outputs elsewhere, set
`CARGO_TARGET_DIR` in the current shell before both preflight and build:

```powershell
$env:CARGO_TARGET_DIR = 'D:/SuzerainDataViewer/artifacts'
cargo build --locked --release
```

The release workflow uses the same pinned compiler and committed `Cargo.lock`.
To verify a build manually, copy a JSON dump to a disposable working directory and run the
built executable there. The converter writes `out/` in its working directory; it does not
modify the source dump. For query validation, import the legacy dumps into a disposable
database and run the commands in the CLI guide. No automated test framework is required.
The observations for this change are recorded in [P1 validation](docs/P1_VALIDATION.md).
